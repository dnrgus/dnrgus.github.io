BUG BOUNTY / ACTIVITY 03

CVE 재현과 LLM 보안 자동화로 다진 기반

알려진 취약점을 이해하고 재현하는 활동과 실제 버그바운티 성과를 구분하면서, 책임 있는 테스트를 위한 도구를 만들었습니다.

1. 공개 CVE를 구조적으로 읽기

React Server Components의 역직렬화 문제인 React2Shell(CVE-2025-55182)과 Windows Notepad 마크다운 렌더링의 CVE-2026-20841을 정리했습니다. 취약한 기능, 공격에 필요한 조건, 영향 범위, 완화 방법을 나누어 기록했습니다.

이 활동은 새로운 취약점을 최초 발견한 것이 아니라 공개된 CVE를 분석한 것입니다. “어디가 위험하다”는 결론보다 입력이 어떤 경로를 거쳐 위험한 동작으로 이어지는지 설명하는 연습에 초점을 맞췄습니다.

2. Fuzzing-101으로 크래시를 재현하기

AFL++로 Xpdf 3.02를 퍼징해 무한 재귀와 스택 고갈로 이어지는 CVE-2019-13288을 재현했습니다. 이어서 libexif 0.6.14를 대상으로 조작된 EXIF 입력이 힙 버퍼 오버플로와 범위 밖 읽기를 유발하는 CVE-2009-3895, CVE-2012-2836을 확인했습니다.

퍼징 환경 구성, 계측 빌드, 크래시 입력 확보, GDB 분석을 한 흐름으로 경험했습니다. 이미 알려진 취약점이더라도 크래시가 발생했다는 사실과 원인을 설명할 수 있다는 것은 다른 단계였습니다.

3. Scope first 자동화 프로젝트

LLM-BugBounty-Automation은 허가된 LLM·RAG·AI Agent·웹 기반 AI 서비스를 반복 가능하게 점검하기 위한 프로젝트입니다. 실행 전에 대상 범위와 프로그램 정책을 확인하고, 허용되지 않은 도메인·기법·요청량은 차단하는 구조를 우선했습니다.

테스트 결과는 실행 로그, 판정, Finding, Evidence, 재현 정보, 보고서로 이어집니다. 민감한 값은 삭제하거나 가리고, 한 번 나온 결과는 반복 시도와 negative control을 통해 다시 확인하도록 설계했습니다. 도구를 많이 실행하는 것보다 재현 가능한 근거를 남기는 것이 목표였습니다.

4. 현재 위치를 정확히 적기

2026년 11월 현재 공개된 T-blog와 GitHub에서는 실제 버그바운티 프로그램에 제출해 접수·채택·보상받은 기록을 확인할 수 없습니다. 따라서 지금까지의 활동은 취약점 분석·재현과 테스트 자동화 기반 구축으로 표현하는 것이 정확합니다.

다음 단계는 허가된 프로그램 또는 의도적으로 취약하게 만든 로컬 환경에서 수동 검증을 병행하고, 정책 확인부터 재현 절차와 영향 분석까지 갖춘 모의 보고서를 축적하는 것입니다.
