Go로 만든 파일 공유 서비스 개발기

파일을 올리면 공유 링크가 생기는 서비스를 Go로 만들었다. 개발의 중심은 기능 자체보다 올라온 파일을 어떻게 안전하게 받느냐에 있었다.

무엇을 만들었나

처음 목표는 단순했다. 파일을 올리면 누구든 받을 수 있는 링크를 만드는 것이었다. 웹 화면에서 드래그 앤 드롭으로 올리는 방식도 되고, curl -F나 curl -T로 올리는 방식도 되게 했다. 올라간 파일은 /f/랜덤ID/파일명 형식의 링크로 내려받는다. 기본 만료는 24시간이고, 다운로드 쪽은 curl -OJ와 Range 요청을 통한 이어받기를 지원하도록 했다.

삭제는 업로드할 때 받은 삭제 키가 있어야만 되도록 했다. 링크만 알고 있는 사람이 파일을 지울 수 없게 하려는 선택이었다.

업로드를 가장 많이 고민했던 이유

파일 업로드는 낯선 사람이 서버에 데이터를 놓도록 허락하는 기능이다. 설계를 잘못하면 서버를 장악당하거나 다른 사용자를 공격하는 발판이 된다. OWASP가 다루는 제한 없는 파일 업로드 취약점이 바로 이 지점이다. 그래서 이 프로젝트에서는 기능을 붙이는 것보다 공격자가 무엇을 올릴 수 있는지를 먼저 막았다.

허용 확장자는 텍스트, 문서, 이미지, zip 같은 일부로 좁혔다. .txt, .md, .csv, .json, .log, .pdf, 이미지 몇 종류, .zip, .docx, .xlsx, .pptx까지만 받는다. 기본 최대 크기는 20MB다. 확장자만 보면 부족하다고 생각해서 MIME 타입 검증과 경로 검증도 함께 넣었다. 파일 이름에 경로 문자가 섞여 있으면 저장하지 않는다.

구현 방식

런타임 의존성 없이 Go 1.22 표준 라이브러리만 쓰기로 했다. 외부 패키지가 늘어나면 보안 점검 범위도 같이 늘어나기 때문이다. 웹 화면의 HTML, CSS, JavaScript는 go:embed로 바이너리 안에 넣었다. 배포 설정은 Docker와 Caddy로 잡았다.

이 서비스는 로그인 없이 쓰는 임시 전달 도구다. 장기 보관이나 협업용 저장소가 아니라는 점을 README에 분명히 적었다. 기능을 조금 더 붙이고 싶은 유혹이 있었지만, 이 범위를 넘기면 보안 검증을 다시 해야 한다고 판단해서 참았다.

돌아보며

만들고 나서 보니 가장 오래 고민한 부분은 만료와 삭제였다. 만료는 파일을 언제 지울지 정하는 문제이고, 삭제는 누가 지울 수 있는지 정하는 문제였다. 두 가지가 맞물려야 임시 파일이 임시로 남는다. 이 과정을 글로 옮기면서 업로드 기능 하나에도 여러 검증 층이 필요하다는 것을 확인했다.

요청 하나가 지나가는 길

파일이 서버에 도착하는 순서를 따라가 보면 설계의 방향이 더 분명해진다. 먼저 요청 본문의 크기를 제한한다. 그다음 multipart 형식을 해석하고, 파일 이름에서 경로 문자를 걸러낸다. 확장자와 MIME 타입을 확인하고 나서야 디스크에 쓴다. 이 순서를 바꾸면 중간 단계에서 임시 파일이 남을 수 있어서, 검사를 앞에 두는 쪽으로 정했다.

저장할 때는 원래 파일 이름을 그대로 쓰지 않고 랜덤 ID를 디렉터리 이름으로 쓴다. 사용자가 올린 이름은 메타데이터로만 보관하고, 다운로드할 때 Content-Disposition에 붙여 준다. 이렇게 해 두면 같은 이름의 파일이 여럿 올라와도 서로 덮어쓰는 일이 없다.

만료와 정리

기본 만료는 24시간으로 두었다. 만료된 파일을 정리하는 작업은 요청이 들어올 때마다 돌리는 방식이 아니라, 주기적으로 도는 정리 루틴으로 분리했다. 요청 경로에 정리 로직을 섞으면 응답 시간이 들쭉날쭉해지고, 정리 중 실패가 생기면 원인을 찾기도 어렵다.

삭제 키는 업로드할 때 한 번만 보여 준다. 서버에는 키의 해시만 남긴다. 키를 잃어버린 경우에는 되돌릴 방법이 없다는 점을 화면에도 적어 두었다. 임시 전달 도구라는 목적을 생각하면 이 정도의 불편은 감수할 만하다고 판단했다.

배포하며 생긴 생각

Docker와 Caddy로 배포 설정을 잡으면서, 애플리케이션이 직접 HTTPS를 다루지 않아도 되는 구조가 편하다는 것을 알게 됐다. 인증서 갱신과 보안 헤더는 Caddy가 맡고, Go 코드는 파일을 받고 돌려주는 일에만 집중한다. 역할이 나뉘니 점검할 범위도 줄었다.

소스 코드는 GitHub에서 볼 수 있다. github.com/dnrgus/go-secure-fileshare

직접 써 보기

실제로 돌아가는 서버 주소다. 개인 PC에서 Docker 컨테이너로 실행하고 Cloudflare 임시 터널로 연결했다. 그래서 PC가 꺼지거나 터널이 끊기면 열리지 않을 수 있다.

https://pipeline-government-move-invisible.trycloudflare.com/

curl로 올리는 예시는 다음과 같다.

curl -F "file=@./report.txt" https://pipeline-government-move-invisible.trycloudflare.com/upload

첨부 파일

서비스의 Go 소스 파일을 그대로 내려받을 수 있게 올려 두었다. 저장소와 같은 내용이다.

  • main.go: 설정 로드, 서버 기동, graceful shutdown
  • server.go: 라우팅, 미들웨어, 보안 헤더
  • upload.go: 업로드 처리와 검증 순서
  • download.go: 다운로드와 삭제
  • validate.go: 파일명, 확장자, MIME, Content-Disposition 검증
  • store.go: 디스크 저장소, 만료 정리, 삭제 키 확인
  • ratelimit.go: IP별 속도 제한
  • server_test.go: 통합 테스트와 공격 시나리오
  • validate_test.go: 파일명과 MIME 단위 테스트
