Git 배우기 기록

Git 실습 문제를 한 단계씩 따라가며 정리했다. 명령을 외우기보다 커밋 그래프가 어떻게 바뀌는지 그려 보는 쪽에 시간을 썼다.

기본과 상대 참조

가장 처음에는 커밋이 무엇인지부터 잡았다. 커밋은 저장소에 있는 모든 파일의 스냅샷을 기록하는 것인데, Git은 가볍게 유지하려고 이전 버전과 다음 버전만 저장한다고 한다. 브랜치는 그 커밋을 가리키는 이름표이고, HEAD는 지금 체크아웃된 커밋을 가리킨다.

상대 참조를 배우면서 HEAD~와 ^ 표기가 헷갈렸다. 병합 커밋에서 어느 부모를 따라갈지 고르는 것이 ^ 숫자라는 점을 이해하고 나서는 훨씬 편해졌다.

rebase와 cherry-pick

고급 문제에서는 9천 번이 넘는 리베이스 문제가 나왔다. 브랜치 여러 개를 main 위로 옮기는 연습이었다. 중간에 브랜치 스파게티라는 문제가 나왔는데, 여러 브랜치에 흩어진 커밋을 cherry-pick으로 한 줄에 모으는 것이 목표였다.

cherry-pick은 현재 위치 아래의 특정 커밋들을 복사해 오는 명령이다. interactive rebase는 -i 옵션으로 커밋 순서를 바꾸거나 합치고 수정하는 데 쓴다. 종합 문제에서는 rebase -i로 순서를 맞추고, commit --amend로 내용을 고친 다음 다시 순서를 맞췄다.

원격 저장소

원격 저장소는 백업이면서 다른 사람과 작업을 나누는 자리라는 설명으로 시작했다. push와 pull의 흐름을 익히고, origin 같은 원격 브랜치 이름이 로컬 브랜치와 어떻게 다른지 보았다.

마지막 문제에서는 feature 브랜치를 원격 main 위로 rebase하고 push하는 흐름을 연습했다. 왜 merge 대신 rebase를 쓰는지 질문이 나왔는데, 원격 기록을 깔끔하게 한 줄로 유지하려는 목적이라는 설명을 읽고 이해했다.
