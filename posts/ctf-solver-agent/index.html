CTF 풀이 에이전트 포크 정리

문제 하나에 여러 LLM 솔버를 붙여 경쟁시키는 CTF 풀이 도구를 포크해서 손봤다. 기반이 된 두 프로젝트를 읽고 어떤 부분을 가져왔는지 정리했다.

어떤 도구인가

이 저장소는 한 문제에 여러 LLM 솔버 인스턴스를 병렬로 돌린다. 각 인스턴스는 자기만의 Docker 샌드박스 안에서 움직이고, 중간에 찾은 단서를 서로 공유한다. 먼저 플래그를 확정하는 쪽이 이기는 구조다.

처음 이 구조를 보았을 때는 솔버끼리 정보를 섞으면 오히려 틀린 가설이 퍼지지 않을까 걱정했다. 실제로 README를 보니 공유하는 것은 findings이고, 플래그로 인정되는 것은 확정된 결과뿐이었다. 우연히 맞아 보이는 문자열과 실제로 풀린 문제를 구분하려는 설계였다.

두 프로젝트를 합친 방식

저장소는 yakisoba0728/ctf-solver-agent를 기반으로 하고, verialabs/ctf-agent에서 재시도와 bump 로직, 서비스 접속 안내 프롬프트를 가져와 합쳤다. 원본 프로젝트는 BSidesSF 2026 CTF에서 52문제를 모두 푼 팀의 도구라고 소개되어 있었다. 합치는 과정에서 생긴 변경 사항은 MERGE_NOTES.md에 따로 정리해 두었다.

기반 프로젝트는 여러 모델 제공자를 하나의 인터페이스로 다루고, CTFd 같은 플랫폼과 자동으로 연동하지 않는다. 문제는 사람이 직접 넣는 방식이다. 터미널 UI는 Textual로 만들어져 있다.

작업하면서 느낀 점

자동 풀이 도구를 다루다 보면 결과보다 과정을 믿기 어렵다는 생각이 든다. 그래서 이 포크에서는 성공 판정 조건을 가장 먼저 확인했다. 샌드박스를 나눈 이유도 같은 맥락이다. 솔버 하나가 망가져도 다른 솔버가 영향을 받지 않아야 했다.
